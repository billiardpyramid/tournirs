# Ближайшие турниры по русскому бильярду (пирамида)

Статический сайт со списком ближайших турниров по пирамиде: свободная, комбинированная,
динамичная, омка. Пул, снукер, карамболь, дартс и фишки не включены.

**Сайт:** https://billiardpyramid.github.io/tournirs/
**Счётчик посещений:** https://github.com/billiardpyramid/tournirs/graphs/traffic
(Insights → Traffic, скользящие 14 дней; вместе с роботами, поэтому цифра заниженная)

## Как это работает

Данные собирает GitHub Actions **два раза в сутки — 07:30 и 19:30 МСК**, без участия
чьего-либо компьютера. Сборщик ходит на площадки обычными HTTP-запросами, отбирает
пирамиду, выкидывает уже начавшиеся турниры, сортирует всё по дате и времени и вставляет
результат прямо в страницу. Изменения коммитятся в ветку `Pyramid_tournirs`, после чего
GitHub Pages сам пересобирает сайт.

Турниры, которые уже начались, на сайт не попадают. Если площадка временно не отвечает,
подставляются данные из кэша и внизу страницы появляется красная плашка; если данным
больше трёх суток — жёлтая. Когда всё в порядке, плашки нет.

## Источники данных

| Метка | Площадка | Что даёт |
|---|---|---|
| ЛЛБ | https://www.llb.su/tournaments/next | общероссийская лента турниров по всем регионам |
| МСБС | https://mosbilliard.ru/calen/ | официальный календарь Москвы и России |
| B4Y | https://bill4you.ru/rus-billiard | только пирамида, много любительских турниров |
| ФБСР | годовой календарь в PDF | ссылка на официальный календарь, автоматический разбор не сделан |

У ЛЛБ и B4Y ведёт ссылка на страницу конкретного турнира. У МСБС отдельных страниц нет —
там ссылка ведёт на общий календарь.

## Что внутри

- `billiard-tournaments.html` — рабочая копия сайта и источник правок вёрстки.
- `index.html` — та же страница, её GitHub Pages и отдаёт посетителям. Сборщик обновляет
  оба файла одинаково, руками править `index.html` не нужно.
- `tools/` — сборщик: `update.mjs` (сбор + фильтры + кэш + запись страницы),
  `build.mjs` (подстановка данных в готовый HTML), `check.mjs` (сверка с площадками
  и проверка хронологии), `lib/` — по файлу на площадку.
- `data/` — `rows.json` (текущее состояние), `cache-*.json` (запас на случай сбоя),
  `last-run.json` (отчёт последнего запуска).
- `.github/workflows/update.yml` — расписание. Лежит в ветке `main`, потому что GitHub
  читает отложенные запуски только из ветки по умолчанию; код и сайт лежат в `Pyramid_tournirs`.

Внутри страницы данные — это массив `ROWS` в `<script>`, внешних библиотек нет.
В каждой строке поля: ключ даты, время, название, город, площадка, вид, число участников,
метка источника, класс источника и ссылка на турнир.

## Локальный запуск

```bash
npm install
npm run update     # собрать данные и записать страницу
npm run check      # сверить с площадками и проверить хронологию
npm run all        # сбор и проверка подряд
```

Ручной запуск того же сбора на GitHub: вкладка **Actions** → «Обновить расписание» →
**Run workflow**.

## Ветки

- `main` — ветка по умолчанию, здесь расписание и ручной запуск сборки.
- `Pyramid_tournirs` — сайт, сборщик и данные. Pages публикует эту ветку.
